# dejaview-frontend

Одностраничное приложение: мультимодальный поиск фильмов и личный кинотрекер.

## Зона ответственности

- Четыре режима поиска в одном окне: текст, изображение, видео, аудио
- Загрузка файлов до 50 МБ: прогресс и отмена, загрузка и обработка показаны отдельно
- Страница фильма: постер, оценки, актёры, сюжет, отзывы
- Профиль: списки «Хочу посмотреть» и «Просмотрено», история, статистика
- Пустые состояния и экраны ошибок
- Адаптивная вёрстка от 360 px

## Стек

- React 19, TypeScript, Vite
- Состояние: Effector + @effector/router, данные: Farfetched + zod
- UI: React Aria Components, стили: Tailwind CSS 4
- Тесты: Vitest + Testing Library
- Типы и zod-схемы API генерируются из `dejaview-docs/api/openapi.yaml` инструментом `@hey-api/openapi-ts`, руками не пишутся
- Конфигурация из переменных окружения, секреты в репозиторий не попадают

## Как поднять локально

```
pnpm install && pnpm start:dev
```

Приложение — на `http://localhost:5173`. Без настроек открываются страницы, но запросы к API не работают. Выберите вариант.

**Пока нет backend** — заглушки API. Создайте в корне файл `.env.development.local`:

```
VITE_API_MOCKS=true
```

Войти можно кнопкой «Войти (заглушка)» на `/login`, вход сохраняется после перезагрузки. Сценарии ответов — в разделе «Заглушки» [`src/shared/api/README.md`](src/shared/api/README.md).

**Backend запущен локально** — в том же файле:

```
VITE_API_MOCKS=false
VITE_API_PROXY_TARGET=http://localhost:8080
```

После изменения переменных перезапустите `pnpm start:dev`. Файл `.env.development.local` читается только при разработке: в сборку и в git он не попадает.

### Переменные окружения

Все настройки необязательны. Шаблон со всеми переменными — `.env.example`, его можно скопировать в `.env.development.local` (`Copy-Item .env.example .env.development.local` в PowerShell, `cp .env.example .env.development.local` в bash).

| Переменная                  | Где используется                                               | По умолчанию                        | Пример                               |
| --------------------------- | -------------------------------------------------------------- | ----------------------------------- | ------------------------------------ |
| `VITE_URL`                  | хост dev-сервера                                               | `localhost`                         | `127.0.0.1`                          |
| `VITE_PORT`                 | порт dev-сервера                                               | `5173`                              | `3000`                               |
| `VITE_API_URL`              | демо-запрос из каркаса, к API DejaView не относится            | —                                   | `https://api.example.com`            |
| `VITE_API_BASE_URL`         | адрес API вместе с `/api/v1`, подставляется при сборке         | `/api/v1`                           | `https://dejaview.example.ru/api/v1` |
| `VITE_API_MOCKS`            | `true` — ответы из заглушек, только для разработки             | `false`                             | `true`                               |
| `VITE_MOCK_SEARCH_SCENARIO` | сценарий ответа поиска при включённых моках                    | `found`                             | `empty`                              |
| `VITE_API_PROXY_TARGET`     | куда dev-сервер пересылает `/api/v1`                           | не задана, proxy выключен           | `http://localhost:8080`              |
| `OPENAPI_SPEC`              | путь к контракту для `pnpm api:generate`, задаётся в терминале | `../dejaview-docs/api/openapi.yaml` | `D:\docs\api\openapi.yaml`           |

## Запуск в Docker

Соберите образ и запустите контейнер:

```sh
docker build -t dejaview-frontend .
docker run --rm -p 5173:5173 dejaview-frontend
```

Приложение откроется на `http://localhost:5173`. Сборка выполняется через pnpm версии из `package.json`; Node.js 22.18.0 и Nginx 1.30.6 зафиксированы в `Dockerfile` вместе с digest образов. Имена базовых образов содержат реестр `docker.io`, поэтому для Podman/Buildah не требуется настройка поиска коротких имён. В итоговом образе находятся Nginx и собранная статика; контейнер запускается от пользователя `nginx` без root. Nginx слушает IPv4-порт `5173` и отдаёт `index.html` для маршрутов приложения, поэтому прямые ссылки и обновление страницы работают. Отсутствующие файлы в `/assets/` возвращают 404.

HTML отдаётся с `Cache-Control: no-cache`, хешированные файлы из `/assets/` — с `public, max-age=31536000, immutable`. Для CSS, JavaScript, JSON и SVG включено gzip-сжатие, если клиент его поддерживает и размер ответа не меньше 1024 байт. Все ответы содержат `X-Content-Type-Options: nosniff`; версия Nginx скрыта.

Адрес API задаётся **при сборке** через `VITE_API_BASE_URL`, по умолчанию `/api/v1`:

```sh
docker build --build-arg VITE_API_BASE_URL=https://dejaview.example.ru/api/v1 -t dejaview-frontend .
```

Параметры `docker run -e` не меняют адрес API в готовой статике: для изменения нужна повторная сборка. Локальные `.env`-файлы исключены из контекста Docker, заглушки API в образе выключены.

Для `/api/v1` нужен внешний reverse proxy, который направляет API-запросы в backend, а страницы — в контейнер frontend на порт `5173`. Nginx в образе обслуживает только статику; `VITE_API_PROXY_TARGET` применяется только к локальному серверу Vite. Запросы к `/api` и `/api/…`, попавшие напрямую во frontend, получают 502, чтобы ошибка настройки proxy не маскировалась HTML-страницей с кодом 200.

В `dejaview-infra` frontend запускается командой `docker compose --profile infra --profile app up frontend` и по умолчанию доступен на `http://localhost:57437`. Оба профиля нужны для валидации текущего `compose.yaml`: с одним `--profile app` он выдаёт ошибку зависимости `db-migrate` от отключённого `postgres`. Сервис использует образ `ghcr.io/dejaview-nsu/dejaview-frontend` с тегом из `FRONTEND_TAG` (по умолчанию `latest`); публикацией образов занимается шаг `build-image` в CI.

## Главная страница и поиск

Текст, изображение и видео запускают поиск через API-клиент. При `VITE_API_MOCKS=true` HTTP-отправка заменяется mock transport, а разбор ответа, обработка ошибок и логика экрана остаются общими. Аудио отображается как недоступный для запуска режим.

Интеграция изображения и видео следует [контракту backend](https://github.com/dejaview-nsu/dejaview-docs/blob/main/api/openapi.yaml): `POST /api/v1/search/image` и `POST /api/v1/search/video`, один файл в поле `file` тела `multipart/form-data`. Интерфейс использует ответ `{ results: [...] }`; пустой массив означает отсутствие результата. Сессия проверяется через `GET /api/v1/auth/session`, ошибки `SESSION_REQUIRED` и `SESSION_EXPIRED` переводят пользователя на вход. SPA обращается только к application server; ML-сервис, PostgreSQL и TMDB вызываются внутри backend.

Для подключения backend задайте `VITE_API_BASE_URL` либо `VITE_API_PROXY_TARGET` и выключите моки. Интеграция проверена с mock transport; проверка с работающим сервером остаётся отдельным шагом.

Тест `tests/pages/home/search-mocks-integration.test.tsx` проверяет путь от выбора файла и кнопки поиска через API-клиент до результата или сообщения на странице: оба файловых режима, состав multipart-запроса, пустую выдачу, ошибки сервиса и файла, повторную попытку и потерю сессии. Подменяется только декодирование медиа, недоступное в jsdom; его отдельные проверки находятся в `tests/shared/lib/files.test.ts`.

- Неавторизованному пользователю доступен только поиск по тексту. При выборе изображения, видео или аудио он переходит на вход. После входа он возвращается на главную; текст и файлы сохраняются до перезагрузки, в том числе при переключении режимов и переходах между страницами.
- Общий загрузчик поддерживает выбор одного файла, перетаскивание и замену. В режиме изображения доступна вставка через Ctrl+V/Cmd+V.
- Перед отправкой проверяются формат, размер, читаемость файла; у видео — длительность. Изображения: JPG/JPEG/PNG/WEBP до 10 МБ. Видео: MP4/MOV/WEBM до 50 МБ и 30 секунд.
- Текстовый поиск доступен гостю: `POST /api/v1/search/text`, JSON `{ query: "..." }`. Описание проверяется после обрезки пробелов по краям, от 3 до 250 символов Unicode. Запуск показывает индикатор поиска и поддерживает отмену; описание сохраняется при переключении режимов и повторных попытках.
- Во время поиска показаны загрузка и обработка. Поиск можно отменить; при уходе со страницы он отменяется автоматически. Отмена и завершение сохраняют выбранный файл для повторного поиска.
- Режимы поиска независимы: у каждого свой черновик, ожидание, отмена и результат. Поиск в одном режиме не блокирует другие режимы и не показывается в их вкладках. Уход со страницы отменяет поиск во всех режимах, выход из аккаунта — поиск по изображению и видео.
- Изображение и видео показывают один фильм; текст — список фильмов из ответа. У каждого результата есть ссылка на карточку. Для пустого ответа и ошибок предусмотрены сообщения. Недоступный постер заменяется заглушкой.

Главная разделена по FSD:

- `pages/home` собирает экран, содержит простые блоки `ui/home-intro.tsx` и `ui/how-it-works.tsx`, создаёт `$$home.$$search` и связывает его с маршрутом и входом.
- `widgets/movie-search` владеет переключением режимов, черновиками, формой, состояниями и результатом. Экземпляр передаётся один раз: `<MovieSearch $$model={$$home.$$search} />`. Внутренние компоненты читают его через `useMovieSearchModel()` и `useUnit()`.
- `features/search-by-file` — проверка изображения, запуск и отмена поиска по изображению.
- `features/search-by-video` — проверки видео до отправки, разбор ошибок сервера для экрана, запуск и отмена поиска по видео. Подробности — в разделе «Поиск по видео».
- `features/search-by-description` — проверка описания, его черновик, запуск и отмена текстового поиска.
- `entities/movie` отображает найденный фильм и постер. `shared` содержит общий загрузчик, проверку файлов и типизированный `createModelView`.

Модель создаётся на уровне модуля, а `modelView` передаёт готовый экземпляр через React-контекст. Stores обновляются и сбрасываются только через `sample`; ESLint запрещает `.on()` и `.reset()`. Технические эффекты доступны через `__` для тестов и не используются UI. Правила архитектуры, оформления и проверок — в [AGENTS.md](AGENTS.md).

Между слоями используются `@/` и публичные `index.ts` слайсов; внутри слоя — относительные пути. ESLint проверяет направление зависимостей, изоляцию соседних слайсов и запрет импортов мимо публичных API, включая реэкспорты и динамические импорты. `app` и `shared` содержат сегменты, а не слайсы; файлы сборки страниц в корне `pages` могут подключать страницы через их публичные API.

Для проверки включите заглушки, войдите, выберите изображение и загрузите PNG/JPEG. Переключите режим и вернитесь — файл сохранится. Запустите поиск и проверьте прогресс, результат и отмену. Сценарии `empty`, `SEARCH_UNAVAILABLE`, `SESSION_EXPIRED` описаны в документации API-клиента выше.

### Поиск по видео

Модель — `src/features/search-by-video`, экран — компоненты `video-*.tsx` и `search-notice.tsx` в `src/widgets/movie-search/ui`. Отправку файла, прогресс загрузки, отмену запроса и отбрасывание устаревших ответов делает общая `createFileSearchFactory` из `shared/api` (см. [`src/shared/api/README.md`](src/shared/api/README.md)). Фича добавляет проверки до отправки и разбор ошибок для экрана. Тексты, форматы и лимиты — в `features/search-by-video/config/video.ts`.

**Порядок проверки файла** (`features/search-by-video/lib/check-video.ts`): файл выбран → один файл → размер до 50 МБ → формат MP4, MOV или WEBM → видео открывается → длительность до 30 секунд. Проверка останавливается на первом нарушении. Видео открывается раньше проверки длительности, потому что длительность читается из метаданных открытого файла; полную проверку целостности выполняет backend и при ошибке возвращает `FILE_CORRUPTED`.

**Этапы.** `idle` → `validating` (повторная проверка перед отправкой) → `uploading` → `processing` → `done` или `failed`.

- Во время загрузки показан процент. Если размер неизвестен (`$progress = null`), показан неопределённый индикатор.
- Отмена доступна на каждом этапе.
- Выбор другого файла отменяет текущие проверку и запрос; ответы устаревших проверок и запросов отбрасываются.
- Уход со страницы отменяет поиск по видео. Выбранный файл хранится в модели до перезагрузки страницы.
- Длительность в карточке и на превью округляется вниз до секунды.

**Ошибки сервера.** Разбор ответов для экрана — в `features/search-by-video/lib/search-error.ts`. Все сценарии ответов описаны в разделе «Заглушки» [`src/shared/api/README.md`](src/shared/api/README.md).

**Контракт модели.** `createSearchByVideoFactory({ $allowed })`:

- `inputs`: `filesSelected(files)`, `searchPressed()`, `cancelled()`;
- `outputs`: `$files`, `$check` (результат проверки), `$state` (файлы, этап, прогресс, длительность, результат, пустая выдача, ошибка и её тип), `$pending`;
- `__`: `$$videoSearch`, `checkFx` — только для тестов.

## Генерация типов API

```
pnpm api:generate
```

- Запускать после изменения контракта `api/openapi.yaml` в `dejaview-docs`: подтяните репозиторий документации и сгенерируйте заново.
- Результат — `src/shared/api/generated/`. Файлы коммитятся вместе с кодом, который на них опирается, и исключены из lint и format. Руками их не правят.
- `dejaview-docs` нужен только для генерации: сборка, тесты и dev-сервер используют закоммиченные файлы.
- Спецификация по умолчанию лежит рядом с проектом, другой путь задаётся `OPENAPI_SPEC` (см. таблицу выше).

Устройство API-клиента — в [`src/shared/api/README.md`](src/shared/api/README.md).

## Временный обход ошибки роутера

В `@effector/router` 1.2.0 обработчик `block` подключается повторно до завершения асинхронного `POP`,
из-за чего кнопки браузера «Назад» и «Вперёд» зацикливают переход. В `src/shared/routes/routes.ts`
из адаптера удалён необязательный `block`; синхронизация адреса продолжает работать через `listen`.
Проверка доступа к профилю через `chainRoute` сохраняется. При этом `beforeNavigate` не сможет
блокировать нативные переходы браузера, пока действует обход.

Обход можно убрать после обновления роутера с исправлением и проверки `tests/shared/routes/browser-history.test.ts`.
